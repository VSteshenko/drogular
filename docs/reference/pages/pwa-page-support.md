# `PwaPageSupport`

**Namespace:** `drogular`  
**Header:** `<drogular/pwa_page_support.hpp>`  
**Kind:** Utility class

## Purpose

`PwaPageSupport` generates common PWA metadata and service-worker registration markup and stores it in a `RenderContext`.

---

## Public API

### `apply()`

```cpp
static void apply(
    RenderContext& context,
    const PwaOptions& options = {}
);
```

Adds these context values:

| Key | Generated by |
|---|---|
| `manifestLink` | `PwaHtml::manifestLink()` |
| `faviconLink` | `PwaHtml::favicon()` |
| `themeColorMeta` | `PwaHtml::themeColor()` |
| `serviceWorkerRegistration` | `PwaScripts::serviceWorkerRegistration()` |

The default argument uses default-constructed `PwaOptions`.

---

## Example

```cpp
class OfflineReadyPage final : public drogular::TemplatePage {
public:
    void onInit(drogular::RenderContext& context) override {
        drogular::PwaOptions options;
        options.manifestPath = "/assets/manifest.webmanifest";
        options.faviconPath = "/assets/favicon.ico";
        options.themeColor = "#4f46e5";
        options.serviceWorkerPath = "/service-worker.js";

        drogular::PwaPageSupport::apply(
            context,
            options
        );
    }

    std::string templateHtml() const override {
        return R"(
{{{ manifestLink }}}
{{{ faviconLink }}}
{{{ themeColorMeta }}}
{{{ serviceWorkerRegistration }}}
)";
    }
};
```

The generated values are HTML or JavaScript snippets and are normally emitted unescaped in templates.

---

## Behavior

`apply()` only prepares render-context values. It does not register static files, a web manifest, or a service-worker route.

Those resources must be configured separately through `App`, for example:

```cpp
app.staticFiles("/assets", "public/assets");
app.serviceWorker("public/service-worker.js");
```

`App::serviceWorker()` always exposes the configured file at `/service-worker.js`. Changing `PwaOptions::serviceWorkerPath` changes only the generated browser registration URL; it does not create a new route.

An offline page is also separate from this helper. `App::offlinePage()` registers a normal page route, while the service worker itself must decide when to use that route as a fallback.

Calling `apply()` overwrites existing values with the same keys.
